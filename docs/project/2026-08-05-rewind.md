# Rewind 功能需求与任务

> 状态：需求草稿（v1） ｜ 日期：2026-08-05 ｜ 范围：仅需求与任务，不含技术实现细节
> 对齐对象：Claude Code 的 Checkpointing + /rewind

## 1. 概述

为 yepanywhere（封装 Claude / Codex / Gemini / OpenCode SDK 的桌面编码助手）增加与 Claude 一致的 rewind 能力：用户可回到本会话历史中的某条消息，选择**回退对话**和/或**回退代码**，mac 与 windows 双端体验一致。

本轮交付物为**需求与任务拆解**，技术实现细节不在本文范围内。文中标注「（默认假设）」的条目为待确认的需求假设，需在实现前收敛。

## 2. 范围

### In（本轮做）
- Provider：**Claude、Codex**
- **对话回退**：回到历史某条 user prompt，丢弃其后所有内容（本对话内原地回退）
- **代码 Checkpoint 回退**：恢复到该点时的文件状态
- **四种触发方式**全部支持（见 FR1）
- **mac / windows 双端一致**

### Out（明确不做）
- **Gemini**（本轮不支持 rewind）
- **Summarize from/up to here**
- **分支模型 / 版本选择器 / fork 出新会话**：仅做"本对话内原地回退"，回退后尾部不保留为可切换分支
- 技术实现细节（代码接口、文件改动、存储实现等）

## 3. 功能需求（Functional Requirements）

### FR1 触发方式
- FR1.1 输入框为空时**双击 Esc** 打开 Rewind 菜单；输入框有内容时双击 Esc 清空内容（内容进入输入历史，可 `↑` 召回）。（默认假设，对齐 Claude 语义）
- FR1.2 支持 **`/rewind` 命令**打开菜单。
- FR1.3 用户消息悬停出现「**编辑**」按钮，点击进入 rewind 流程。
- FR1.4 会话菜单提供「**Rewind…**」入口打开菜单。

### FR2 Rewind 菜单
- FR2.1 列出本会话**每条 user prompt**（按时间顺序）。
- FR2.2 用户选中某条 prompt 后，展示可选恢复动作（见 FR3）。
- FR2.3 若本会话曾执行 `/clear`，菜单顶部额外提供「**/resume（上一会话）**」入口。（默认假设）

### FR3 恢复动作（Claude 三选项全保留）
- FR3.1 **恢复代码和对话**：将该点之后的对话与代码变更全部回退到该点。
- FR3.2 **恢复对话（保留当前代码）**：仅回退对话，磁盘文件保持现状。
- FR3.3 **恢复代码（保留对话）**：仅将文件恢复到该点状态，对话保持现状。
- FR3.4 **取消**：关闭菜单，不做任何改动。
- FR3.5 回退后，该点之后的消息/代码变更**永久丢弃**；执行前弹**二次确认框**（列出将被丢弃的范围），确认后方可执行。（已定：永久丢弃 + 二次确认）

### FR4 代码 Checkpoint
- FR4.1 每次 user prompt 提交前，对 Claude/Codex 通过**文件编辑工具改动过的文件**做快照。
- FR4.2 Checkpoint 存储于 `~/.yep-anywhere/checkpoints/<sessionId>/<promptId>/`。（默认假设）
- FR4.3 仅快照被编辑工具改过的文件；bash 等外部命令改的文件不在快照内（与 Claude 行为一致）。（默认假设）
- FR4.4 每个会话保留最近 **100** 个 checkpoint；随会话存储，**30 天**（可配置）后随会话清理。（默认假设，对齐 Claude）
- FR4.5 「恢复代码」将快照覆盖的文件写回磁盘；对快照之外的手动编辑文件不改动；若恢复会覆盖用户未保存的手动修改，UI **提示风险**。（默认假设）

### FR5 双端一致性
- FR5.1 mac 与 windows 的功能与交互行为一致。
- FR5.2 快捷键采用平台感知映射（mac 用 `Cmd`、win 用 `Ctrl`，具体组合见 IR1）。

## 4. 交互需求（Interaction Requirements，mac / win）

### IR1 快捷键
- IR1.1 双击 Esc（输入为空）：打开 Rewind 菜单。
- IR1.2 命令面板 `/rewind` 打开菜单。
- IR1.3 建议会话级快捷键 **mac `Cmd+Shift+R` / win `Ctrl+Shift+R`** 作为 Rewind 菜单快捷入口；需确认不与 Tauri webview 刷新等冲突。（默认假设）

### IR2 菜单与模态
- IR2.1 Rewind 菜单采用**应用内 React 模态**（不依赖原生菜单），保证双端视觉与行为一致。
- IR2.2 会话菜单「Rewind…」通过 **Tauri 原生菜单 accelerator** 触发同一模态，mac / win 分别配置 accelerator。

### IR3 二次确认
- IR3.1 执行回退前弹确认框，明确展示「将丢弃该点之后的 N 条消息 / M 个文件变更」，提供确认 / 取消。

## 5. 任务拆解（Tasks，仅目标，不含技术细节）

- **T0 需求与交互定稿**（本文档）
  - 目标：锁定功能 / 交互需求与双端行为，作为后续实现基准。
- **T1 数据 / 存储**
  - 目标：定义 Checkpoint 快照存储结构与位置、rewind 所需元数据；明确"本对话内回退"的状态表达。
- **T2 后端能力**
  - 目标：实现 Checkpoint 捕获（每次 Prompt 前对编辑文件做快照）；实现 rewind/restore（恢复对话 / 恢复代码 / 两者）；接入 Claude `resumeSessionAt` 与 Codex `thread/rollback`。
- **T3 前端**
  - 目标：Rewind 菜单组件（列出 user prompt + 三动作）、用户消息编辑入口、接入现有 `editRewind` 链路、回退前二次确认弹窗。
- **T4 双端适配**
  - 目标：平台感知快捷键（mac `Cmd` / win `Ctrl`）、Tauri 原生菜单 accelerator、输入为空双击 Esc 开菜单的判定逻辑。
- **T5 测试与 Provider 适配**
  - 目标：Claude DAG 投影验证、Codex rollback marker 验证、Checkpoint 捕获 / 恢复正确性、mac / win 双端 e2e。

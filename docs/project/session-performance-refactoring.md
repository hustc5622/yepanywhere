# 会话展示按需工作与依赖整理

## 实施边界

本轮以 `4be239d16` 为起点，逐项处理审计中的局部问题：

- Git 状态仅在检查器打开、Git 标签选中且页面可见时轮询；请求结束后再安排下次轮询，项目切换、关闭、卸载会使旧响应失效。
- 普通文件活动索引和 Codex／Pi 保存版本选择都缓存同版本的 Promise。缓存属于当前路由实例，按 provider、项目、会话、分支（保存版本还包含 store 目录）隔离；失败移除当前条目，旧请求完成不再写回缓存。
- 展示快照缓存记录单个条目的 UTF-16 JSON 大小估算和总量。保留 5 条、32 MiB 上限与最近写入顺序；读缓存不改变淘汰顺序。
- `useSessionInspectorHistory` 接管原先在 SessionPage 中的分页、重试和失效逻辑。关闭检查器、页面隐藏或进入活跃 turn 时停止后续翻页；已完成的历史保留，重新打开时按 revision 刷新。初次失败仍允许手动重试，刷新失败保留已有详情。
- 检查器隐藏时不预处理消息；checks 仅在对应标签计算，文件 fallback 仅在 Files 标签且无服务端索引时计算。plan、subagents、goal 属于公共区域，打开检查器时继续展示。
- 会话页面中的 `TranscriptRendererProvider` 注入嵌套消息和内容块组件，Task renderer 不再反向 import 顶层组件。Provider 保留在懒加载会话页面内，避免把完整渲染树拉进应用首屏入口。
- 摘要聚合函数接收摘要方法，纯元信息和聚合层不再导入 JSX renderer。具体工具的摘要方法与其展示实现仍共同维护；没有为了消除 import 环复制一份摘要逻辑。
- 归档阻塞优先级和公开产物文件名校验移到 shared；没有合并语义已不同的 Codex 两端字面量解析器，也没有按文件行数拆分 provider 状态机。

## 快照缓存测量

复现命令：

```bash
pnpm exec tsx scripts/benchmark-display-snapshot-cache.ts
```

环境：Apple M4 Pro、darwin arm64、Node v25.9.0。每项预热 20 次、采样 100 次；合成 question 节点，每个节点含 1 KiB 文本，更新序号并替换一个会话。以下为一次本机采样，单位毫秒。

| 每条快照估算体积 | 单独 stringify 中位 / P95 | 5 条缓存更新，旧实现中位 / P95 | 5 条缓存更新，新实现中位 / P95 |
| --- | --- | --- | --- |
| 0.273 MiB | 0.027 / 0.105 | 0.135 / 0.252 | 0.026 / 0.033 |
| 1.094 MiB | 0.092 / 0.161 | 0.495 / 0.560 | 0.094 / 0.145 |
| 4.385 MiB | 0.375 / 0.460 | 1.931 / 2.219 | 0.383 / 0.464 |

仅保留一条 4.385 MiB 快照时，更新中位耗时为旧实现 0.380 ms、新实现 0.376 ms，基本没有改善。活跃快照仍完整计量，优化消除的是未变化会话的重复序列化。确定性的工作量回归测试验证：5 条缓存、100 次更新，只计量 100 次，淘汰时不额外序列化。

这些是 Node/V8 合成 CPU 数据，不包含浏览器主线程调度、真实 provider 内容、React commit、布局、设备与网络；不能据此声称页面整体提速比例。32 MiB 也是既有序列化估算预算，不代表真实堆内存上限。下一步若实际大快照仍占据明显主线程时间，再测量节点级增量计量的收益与复杂度。

## 自动守卫

- 保留 services → routes、shared → applications、client → server 的现有禁止反向依赖规则。
- 客户端生产源码的静态运行时 import/export 图禁止依赖环，排除纯类型边与延迟 dynamic import；当前原有 11 文件强连通分量已解除，无旧环豁免。
- 纯工具元信息与摘要聚合的传递依赖不得包含 JSX 文件或 renderer 目录。
- 行为测试覆盖不可见时无 Git 请求／消息预处理、迟到响应隔离、慢请求轮询、关闭停止历史翻页、分支隔离、版本刷新、并发冷扫描合并、失败重试及缓存淘汰预算。

本轮验证使用单元测试、类型检查、lint 和生产构建；没有运行浏览器自动化或操作已有服务。
